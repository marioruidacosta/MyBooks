# MyBooks on iPhone (Kotlin Multiplatform) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move MyBooks into a Kotlin Multiplatform `shared` module with thin Android and iOS apps, and ship the iOS app to TestFlight from GitHub Actions.

**Architecture:** `shared` (KMP: androidTarget + iosArm64 + iosSimulatorArm64) holds domain, data, ViewModels and Compose Multiplatform UI; platform differences sit behind `expect` declarations and four service interfaces. `androidApp` is the existing app shell; `iosApp` is an XcodeGen project hosting `MainViewController()`.

**Tech Stack:** Kotlin 2.4.21, AGP 9.5.0 (`com.android.application`, `com.android.kotlin.multiplatform.library`), Compose Multiplatform 1.12.2, org.jetbrains.androidx navigation-compose 2.10.0 / lifecycle-viewmodel-compose 2.11.0, Room 2.8.5 + sqlite-bundled 2.7.1, Ktor 3.6.1, xmlutil core 1.0.2, kotlinx-datetime 0.8.0, okio 3.18.2, Coil 3.6.3 (+ coil-network-ktor3), kotlinx.serialization 1.12.0.

**Spec:** `docs/superpowers/specs/2026-10-31-ios-kmp-design.md`

## Global Constraints

- applicationId / bundle id `com.mcosta.mybooks`; Android `versionCode` 3, `versionName` "2.0".
- iOS deployment target 16.0; framework name `Shared`, static.
- Room schema stays version 2 with the existing `MIGRATION_1_2` semantics; exported schemas move to `shared/schemas` (copy `app/schemas/.../2.json`).
- No iOS code can be compiled locally (Windows). Every iOS-only file must be small, behind an `expect`/interface, and is verified only in CI. Never leave commonMain depending on `java.*` or `android.*`.
- Local gate commands (Windows): `./gradlew :shared:testAndroidHostTest :androidApp:assembleDebug` (task names per AGP KMP plugin; if they differ, use `./gradlew tasks --all` and record a ruling).
- Secrets only in `local.properties` (Android) and GitHub Actions secrets (`ASC_KEY_ID`, `ASC_ISSUER_ID`, `ASC_KEY_P8`, `APPLE_TEAM_ID`, `GOOGLE_BOOKS_API_KEY`).
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Downloads on this network need `curl --ssl-no-revoke`; Robolectric tests keep `@Config(sdk=[35])` and the Windows-ROOT trust store setting.

## Review Focus

1. A `.zip` backup made by the current Android app (java.util.zip, DEFLATE entries) must import with the new common ZIP reader → Task 5 test reads a committed fixture produced by `java.util.zip`.
2. Upgrading the installed Android app (Room v2 database at `mybooks.db`) must keep all books → Task 7 keeps the Robolectric migration test and adds an "open existing v2 file" test.
3. BNP XML with entities (`&amp;`) and the "?" markers must parse identically after the xmlutil switch → Task 4 reuses the real fixtures unchanged.
4. Accent folding must give identical search keys on both platforms ("Ética"→"etica", "José"→"jose") → Task 3 commonTest runs on Android here and on iOS in CI.
5. iOS app with no network / no API key must still allow manual add (lookup errors are messages, not crashes) → Task 10 iOS smoke test in CI launches lookup with a failing engine.
