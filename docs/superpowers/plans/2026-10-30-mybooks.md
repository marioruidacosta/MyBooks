# MyBooks Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An Android app to manage a personal book library: scan ISBN barcodes, auto-fill metadata, rate, annotate, and track Read / To read / Wishlist.

**Architecture:** Single-module Android app (`:app`), Compose UI with one ViewModel per screen, a `BookRepository` over Room plus a lookup service (Google Books → Open Library fallback) and a JSON backup serializer. Dependencies wired by hand in an `AppContainer` owned by the `Application`.

**Tech Stack:** Kotlin, Jetpack Compose (Material 3), Navigation Compose, Room (KSP), OkHttp, kotlinx.serialization, Coil, Google code scanner (`play-services-code-scanner`), JUnit4, kotlinx-coroutines-test, Robolectric, OkHttp MockWebServer.

**Spec:** `docs/superpowers/specs/2026-10-30-mybooks-design.md`

## Review Focus

1. Manually typed ISBNs with hyphens/spaces (`978-0-306-40615-7`) must normalize, not be rejected → test in Task 2.
2. Google Books items with missing fields (no `imageLinks`, `publishedDate` of `"2005"` or `"2005-03-01"`, no `authors`) must parse to a book with nulls, not throw → test in Task 5.
3. Search text containing `%` or `_` must match literally, not act as wildcards → test in Task 3.
4. Notes typed on the detail screen must not be lost when the user presses Back → saved in `onCleared`/on dispose in Task 9 (manual check listed there).
5. Importing a backup that contains a book with an ISBN duplicated inside the file itself, or a blank title, counts it as failed and keeps the rest (no crash, single transaction for valid rows) → test in Task 6.
